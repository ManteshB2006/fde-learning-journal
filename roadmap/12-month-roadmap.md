# 12-Month Roadmap: Beginner to Job-Ready Forward Deployed Engineer

**Duration:** October 2026 – October 2027  
**Goal:** Become ready to apply for FDE internships and relevant entry-level engineering roles.  
**Learning approach:** Learn → Practice → Build → Test → Deploy → Document → Review  
**Target study time:** 12–15 hours per week

---

## My Goal

Become a Forward Deployed Engineer who can understand real business problems, build software solutions, integrate APIs and AI systems, deploy reliable applications, and communicate technical decisions clearly.

I will measure progress through working projects, demonstrated skills, testing, deployments, and documented problem-solving—not certificates alone.

## Month 1 — Python, Git and Linux Foundations

**Topics**

- Python syntax, variables, data types and operators
- Conditions, loops, functions and collections
- Strings, files, JSON and exceptions
- Modules, packages and virtual environments
- Git, GitHub, commits, branches and merges
- Linux commands, environment variables and file permissions

**Build:** Command-line support-ticket manager using Python and JSON.

**Deliverables**

- Daily Markdown notes
- Python practice programs
- GitHub learning journal
- README with setup and usage instructions

**Success criteria:** Write and debug small Python programs independently and explain Git's basic workflow.

## Month 2 — SQL, Databases and REST APIs

**Topics**

- PostgreSQL, tables, relationships and constraints
- SELECT, INSERT, UPDATE and DELETE
- Joins, grouping, indexes and transactions
- Database normalization and schema design
- HTTP, REST, JSON and status codes
- Requests, authentication, pagination and timeouts

**Build:** Ticket-management REST API backed by PostgreSQL.

**Success criteria:** Design related database tables, write SQL queries, call APIs, and handle common HTTP errors.

## Month 3 — Backend Engineering

**Topics**

- FastAPI, routing and request validation
- Pydantic and dependency injection
- CRUD operations and database integration
- Authentication, authorization and password hashing
- pytest, unit tests and integration tests
- Logging, error handling and database migrations

**Build:** Issue-tracking API with users, roles, tickets, filtering and pagination.

**Success criteria:** Run automated tests, document API endpoints, and handle invalid inputs and failures.

## Month 4 — Full-Stack Development

**Topics**

- JavaScript fundamentals and asynchronous code
- React components, props, state and hooks
- Forms, API requests and error states
- Responsive UI design and accessibility
- Connecting frontend and backend
- Authentication and protected pages

**Build:** Web dashboard for the issue-tracking application.

**Success criteria:** A user can log in, create tickets, filter records and update ticket status through the UI.

## Month 5 — API Integrations and Automation

**Topics**

- Third-party APIs and webhooks
- OAuth fundamentals and API keys
- Pagination, retries, rate limits and timeouts
- Idempotency and duplicate-event handling
- CSV and JSON data transformation
- Scheduled jobs and notifications

**Build:** Automated support-ticket workflow with prioritization and notifications.

**Success criteria:** Integrate an external service and recover safely from temporary failures.

## Month 6 — Docker, Testing and Deployment

**Topics**

- Docker images and containers
- Docker Compose
- Environment configuration and secrets
- GitHub Actions and continuous integration
- Deployment logs and health checks
- Database migrations, backups and basic monitoring

**Build:** Containerized, deployed version of the support application.

**Success criteria:** A fresh setup works using documented instructions, tests run automatically, and deployment failures can be investigated through logs.

## Month 7 — LLM and AI Engineering

**Topics**

- LLM APIs and model selection
- Prompt design and system instructions
- Tokens, context windows and structured outputs
- Tool/function calling
- Streaming, latency and API costs
- Validation, fallbacks and error handling

**Build:** AI support-ticket triage service that categorizes tickets, assigns priority, and drafts suggested responses.

**Success criteria:** Validate model outputs, handle API failures, and measure classification quality and cost per task.

## Month 8 — Retrieval-Augmented Generation (RAG)

**Topics**

- Document parsing and preprocessing
- Chunking and embeddings
- Vector search and retrieval
- Context construction and source citations
- Retrieval evaluation and answer quality
- Document permissions and prompt injection risks

**Build:** Knowledge-base assistant that answers questions from documents with source references.

**Success criteria:** Evaluate retrieval quality, test unsupported questions, and prevent users from accessing unauthorized documents.

## Month 9 — AI Agents and Workflow Automation

**Topics**

- Tool calling and workflow state
- Deterministic workflows versus agents
- Multi-step execution and retries
- Human approval gates
- Audit logs and error recovery
- Prompt injection and action permissions

**Build:** Support-resolution assistant that searches knowledge, drafts responses, and proposes ticket actions for human approval.

**Success criteria:** Handle tool failures and prevent unauthorized or duplicate actions.

## Month 10 — Real-World Business Capstone

**Project:** AI Customer Support Operations Platform.

**Requirements**

- Define the customer problem and target users
- Document requirements and acceptance criteria
- Design the database and system architecture
- Implement ticket ingestion and management
- Integrate AI triage and knowledge retrieval
- Create a dashboard for support staff
- Include authentication, audit logs and approval workflows

**Deliverables**

- Working application
- Architecture diagram
- API documentation
- Deployment instructions
- Demo video or live demonstration

**Success criteria:** A user can complete the primary workflow end to end.

## Month 11 — Production Readiness and Business Impact

**Topics**

- Security and access control
- Integration and failure-recovery testing
- Logging, monitoring and alerting
- AI evaluation and regression testing
- Performance, latency and cost analysis
- User feedback and measurable outcomes

**Tasks**

- Fix issues discovered during testing
- Test timeouts, duplicate events and invalid data
- Document limitations and design trade-offs
- Measure actual performance using a defined test set
- Gather feedback from users who agree to participate

**Success criteria:** Demonstrate reliability, document known limitations, and report real measurements without inventing results.

## Month 12 — Portfolio and Job Preparation

**Technical preparation**

- Python coding and debugging
- SQL queries and schema design
- REST API design and integration
- Testing, Git and Docker
- Basic system design
- LLM, RAG and AI evaluation concepts

**FDE preparation**

- Requirements gathering and discovery questions
- Turning business problems into technical requirements
- Explaining architecture to nontechnical users
- Live demonstrations and troubleshooting
- Communicating trade-offs and project limitations

**Portfolio tasks**

- Polish two or three strong projects
- Improve GitHub READMEs and documentation
- Publish project demos where practical
- Document architecture, testing and deployment
- Prepare honest, evidence-based resume bullets
- Practice technical and behavioral interviews
- Apply for FDE, implementation engineering, solutions engineering, AI application engineering, and backend/full-stack internships

**Success criteria:** Independently demonstrate and explain your projects, discuss engineering trade-offs, and apply to relevant openings.

## Weekly Learning Routine

| Day | Focus |
|---|---|
| Monday | Learn concepts and write notes |
| Tuesday | Solve practice exercises |
| Wednesday | Build a project feature |
| Thursday | Test and debug |
| Friday | Review code and document lessons |
| Saturday | Integrate, deploy and test |
| Sunday | Review progress and plan the next week |

Adapt this routine around college exams and assignments. Consistency matters more than completing every task on a fixed date.

## Daily Documentation Template

For every study session, record:

1. Date and topic
2. Definitions in my own words
3. Code examples and expected output
4. Practice questions and solutions
5. Errors encountered and debugging lessons
6. Real-world application
7. What I can explain independently
8. Next learning target

Commit meaningful work to GitHub after reviewing changes. Never commit credentials, API keys or sensitive information.

## Monthly Review Checklist

At the end of each month, ask:

- [ ] Did I finish the planned practical project or milestone?
- [ ] Can I explain the key concepts without reading my notes?
- [ ] Did I test my code and handle relevant edge cases?
- [ ] Did I document bugs and how I resolved them?
- [ ] Did I publish my progress to GitHub?
- [ ] Can I demonstrate a working result?
- [ ] What are my biggest knowledge gaps?
- [ ] What is the next concrete improvement?

## Rules for the Year

1. Build projects instead of only watching tutorials.
2. Learn fundamentals before adding unnecessary frameworks.
3. Prefer simple, reliable workflows over unnecessarily complex AI agents.
4. Test code and integrations before calling them complete.
5. Deploy applications and document how to reproduce them.
6. Use certificates to support learning, not replace demonstrated skills.
7. Start exploring internships before Month 12.
8. Measure progress through independent problem-solving and working software.

**Final outcome:** A GitHub portfolio demonstrating Python, SQL, backend development, full-stack applications, system integration, AI engineering, testing, deployment, and customer-focused problem-solving.
